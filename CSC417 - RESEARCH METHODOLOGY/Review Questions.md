# Research Methods – Key Concepts

## 1. What is a Research Gap?

A **research gap** is an area, question, or issue that has not been adequately studied or explained in existing literature. It represents missing knowledge that your research aims to address.

### Types of Research Gaps:
- **Knowledge gap** – Missing information on a topic.
- **Methodological gap** – Existing studies use weak or outdated methods.
- **Contextual gap** – Research exists but not in a specific population, region, or setting.
- **Theoretical gap** – Lack of theory explaining a phenomenon.
- **Empirical gap** – Limited or conflicting findings.

## 3. Difference Between Journal and Conference Paper

| Feature | Journal Paper | Conference Paper |
|----------|---------------|------------------|
| Review Process | Rigorous peer review | Peer reviewed but usually shorter review cycle |
| Length | Longer and detailed | Shorter and concise |
| Publication Speed | Slower | Faster |
| Depth of Research | More comprehensive | Often preliminary or focused |
| Prestige | Generally higher | Depends on conference quality |

## 4. Examples of Bad Research Practices

- Plagiarism (copying without citation)
- Fabrication (making up data)
- Falsification (manipulating data)
- Selective reporting of results
- Poor citation practices
- Lack of informed consent
- Data manipulation to fit hypothesis
- Inadequate sample size without justification

## 6. Theoretical Framework vs Conceptual Framework

| Theoretical Framework | Conceptual Framework |
|----------------------|----------------------|
| Based on existing theories | Based on researcher's ideas |
| Uses established models | Developed by researcher |
| Explains why relationships exist | Shows how variables relate |
| Theory-driven | Concept-driven |
| More structured | More flexible |

**Summary:**
- Theoretical framework = existing theory guiding the study.
- Conceptual framework = diagram or model showing variables and relationships in your study.

## 7. Processes in Undertaking a Good Research Work

1. Identify research problem
2. Conduct literature review
3. Identify research gap
4. Formulate research questions/hypotheses
5. Develop research design
6. Collect data
7. Analyze data
8. Interpret results
9. Draw conclusions
10. Make recommendations
11. Write and present report

---

## 8. Justification vs Significance of Study

| Justification | Significance |
|--------------|--------------|
| Explains why the study is needed | Explains who benefits from the study |
| Focuses on the problem | Focuses on impact |
| Addresses urgency or importance | Describes contribution |
| Often linked to research gap | Often linked to stakeholders |

**Simple Difference:**
- **Justification** = Why this research must be done.
- **Significance** = What value the research adds and to whom.

## 9. Explain the Types of Reports

Reports can be classified based on purpose and structure:

### a) Informational Report
Provides facts, data, or findings without analysis or recommendations.  
Example: Survey results report.

### b) Analytical Report
Analyzes data and provides conclusions and recommendations.  
Example: Feasibility report.

### c) Technical Report
Focuses on technical details of a project or research.  
Common in engineering and computer science.

### d) Research Report
Presents results of a scientific investigation.

### e) Progress Report
Shows the current status of an ongoing project.

### f) Feasibility Report
Evaluates whether a proposed project is practical or achievable.

### g) Executive Summary
A short summary of a full report written for decision-makers.  
It highlights:
- Purpose of the report
- Key findings
- Conclusions
- Major recommendations  

It allows readers to understand the main points without reading the entire document.

### h) Laboratory (Lab) Report
A detailed report describing an experiment conducted in a laboratory.  
It usually includes:
- Aim
- Materials
- Procedure
- Results
- Discussion
- Conclusion  

Used mainly in science and engineering practicals.

### i) Field Report
A report based on observations or data collected outside the laboratory (real-world environment).  
It describes:
- Location and setting
- Methods of data collection
- Observations
- Findings  

Common in environmental studies, sociology, IT field training (SIWES), etc.

## 10. Component Structure of a Computer Science Student Technical Report

A standard technical report usually includes:

### Preliminary Pages
1. Cover Page
2. Title Page
3. Certification/Approval Page
4. Dedication (optional)
5. Acknowledgement
6. Abstract
7. Table of Contents
8. List of Figures
9. List of Tables

### Main Body
10. Chapter One: Introduction  
   - Background of Study  
   - Problem Statement  
   - Aim and Objectives  
   - Research Questions  
   - Scope of Study  
   - Justification/Significance  

11. Chapter Two: Literature Review  
12. Chapter Three: System Analysis and Design  
   - Existing System  
   - Proposed System  
   - System Architecture  
   - Design Diagrams  

13. Chapter Four: System Implementation  
   - Tools and Technologies Used  
   - Program Modules  
   - Testing  

14. Chapter Five: Summary, Conclusion and Recommendations  

### End Matter
15. References  
16. Appendices (Source Code, Questionnaires, Screenshots, etc.)

## 11. Explain Flowchart, Pseudo-code, Use-Case Diagram, and Class Diagram

### a) Flowchart
A graphical representation of an algorithm or process using symbols such as:
- Oval (Start/End)
- Rectangle (Process)
- Diamond (Decision)
- Parallelogram (Input/Output)
- Arrows (Flow direction)

It shows the step-by-step flow of a program or system.

---

### b) Pseudo-code
A simplified, human-readable description of an algorithm.  
It resembles programming logic but is not written in any specific programming language.

Example:
```
START  
INPUT number  
IF number > 0  
PRINT "Positive"  
ELSE  
PRINT "Negative"  
END
```

---

### c) Use-Case Diagram
A UML diagram that shows:
- Actors (users or external systems)
- Use cases (functions of the system)
- Relationships between actors and system functions  

It describes how users interact with a system.

---

### d) Class Diagram
A UML diagram that shows:
- Classes
- Attributes (variables)
- Methods (functions)
- Relationships (inheritance, association, aggregation)  

It represents the structure of an object-oriented system.
